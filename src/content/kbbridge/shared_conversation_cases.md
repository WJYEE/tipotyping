# KB-Bridge 공유 대화에서 추가한 사례·메모

> 자료: 사용자가 제공한 2026-10-13 대화 텍스트. 아래는 학습에 유용한 내용을 주제별로 재구성한 것이며 원문 전체를 재배포하지 않습니다. 채용 일정은 당시 공유된 기록으로 현재 유효성 미확인입니다.

## 1. 금융 IT: 계정계·채널계·정보계
- 계정계: 실제 계좌·거래 등 핵심 원장을 처리하는 시스템. 채널계: 앱·웹·창구 등 고객 접점. 정보계: 분석·보고에 필요한 데이터 활용 영역.
- **사례 토론:** 생체인증 결제 오인식이 발생할 때 추가 인증, 이상거래 탐지, 차단, 복구, Fallback을 어떻게 설계할지 논의한다.
- **[파생질문]** 채널계의 인증 성공을 계정계의 거래 승인으로 즉시 연결하면 어떤 위험이 발생하는가?
- 주의: 이 사례에서 제시된 아키텍처는 교육용 가정이며 특정 서비스의 실제 내부 구현을 뜻하지 않는다.

## 2. 데이터 모델링과 ERD
- 1:N: 하나의 채널에 여러 영상. N:M: 한 학생이 여러 곡을 저장하고 한 곡을 여러 학생이 저장. N:M은 연결 테이블로 구현한다.
- **[파생질문]** 학생과 강의가 N:M이면 수강신청 테이블의 기본키/유니크 제약을 어떻게 설정할까?

## 3. 실무 자동화와 API
- n8n 금융 자동화 템플릿을 참고해 RSS 수집, DART 공시 알림, Google Sheets 연동 등 반복업무 자동화 실습을 설계한다.
- 공개 Google Sheets에 대한 API 키 접근과 비공개 문서에 대한 서비스 계정/인증 요구사항을 구별한다. 접근 권한은 공식 API 문서로 재검증한다.
- **[파생질문]** 워크플로우가 재시도되더라도 같은 뉴스가 두 번 발송되지 않게 하려면?

## 4. 데이터·서비스 기획 사례
- 컬리 CRM 쿠폰 발송 사례를 참고해 고객 행동에 따른 메시지 전략과 성과 지표를 역기획한다.
- 토스 앱 역기획 사례를 참고해 문제 정의→가설→개선안→측정 지표로 문서화한다.
- **[파생질문]** 쿠폰 발송 효과를 보려면 클릭률 외 어떤 실험·가드레일 지표가 필요한가?

## 5. 금융권 취업 준비
- 현직자 Q&A에 따르면 금융 IT 직무에서는 계정계/채널계, 보안 이슈, 프로젝트의 어려움·기술 선택 근거 등을 설명하는 역량이 중요하다는 경험담이 공유되었다. 이는 한 사람의 주관적 사례이며 채용 기준이 아니다.
- 코딩 연습: 프로그래머스, AtCoder, LeetCode, Jungol, SW Expert Academy.
- 금융 산업 분석: 신한인사이트, 하나금융연구소, KB경영연구소, KDB미래전략연구소, 한국은행 경제연구원.
- **[파생질문]** 자신이 만든 금융 데이터 프로젝트의 비즈니스 문제, 검증 방식, 실패/개선 경험을 각각 30초로 설명할 수 있는가?

## 6. 채용 정보 관리 원칙
- 대화에 등장한 2026년 특정 공고·설명회는 만료 가능성이 높으므로 상시 추천 리소스와 분리한다.
- 개인 이름, 사설 네트워크 주소, 접속 비밀번호, 공유된 팀 계정 등은 콘텐츠에 포함하지 않는다.
